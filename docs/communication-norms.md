# Communication Norms

## Where to communicate

Keep project communication on GitHub so the history stays in one place:

- **Bugs and feature requests:** open an issue.
- **Questions:** open an issue with the `question` label.
- **Code changes:** use pull requests and reviews.
- **Security problems and Code of Conduct reports:** email the maintainer privately at sunday.school.software@gmail.com. Don't post these publicly.

If something gets decided outside GitHub (over email or in person), post a short summary on the related issue or PR.

## Response times

Expect a reply to issues, pull requests, and comments within 1 week, and to security or Code of Conduct reports within 72 hours (fixes may take longer).

If a week goes by with no reply, comment again to bump the thread.

The maintainer is a student, so replies may be slower around exams and holidays.

## What we expect from contributors

- Reply to review feedback, or post a progress update, within 2 weeks. Otherwise the issue may be unassigned so someone else can pick it up.
- Open an issue and agree on the approach before starting a large change.

## Making decisions

Discuss disagreements in the issue or PR thread. If the discussion doesn't reach agreement, the maintainer makes the final call and explains why in the thread.

## Tone

Comment on the code, not the person, and assume good intent. All communication falls under the [Code of Conduct](../CODE_OF_CONDUCT.md).

## Privacy

Never post members' real names, email addresses, or phone numbers in issues, PRs, or comments. Use placeholders like "Teacher A" instead.
